# ADR-009: Формат данных v2 — поля из полного набора макетов

**Статус:** Принято (2026-09-25)
**Дата:** 2026-09-24
**Решает:** владелец (поля и их смысл), Claude (условия присутствия, переход, слияние)
**Уточняет:** ADR-003 (контракт данных), ADR-004 (слияние), ADR-005 (`status.json`)

## Контекст
Полный набор макетов (31 экран) требует данных, которых в формате v1 нет:
- статистика дедлайнов «в срок / перенесено / сорвано» — нужен первый срок задачи;
- «Стали проектами» и текст идеи в карточке — нужна связь проекта с идеей;
- «→ Опубликовано 02.09» на плитке «готово» — нужна дата перехода в «готово»;
- идея, привязанная к проекту, — ссылка идеи на проект;
- «Последний коммит · main», «Деплой · Netlify» — ветка по умолчанию и провайдер деплоя в `status.json`.

Владелец решил: обложка остаётся только вырезанным кадром 16:6 (`coverCrop` не нужен), дату «Опубликовано» хаб ставит сам, заброшенность считается по логу и коммитам.

## Решение

### 1. Принцип: у каждого нового поля — условие присутствия
Поле не «необязательное на всякий случай»: схема задаёт, когда оно есть (`if/then`, `dependentRequired`). Вычисляемое (прогресс, «горит», сводки, заброшенность, доля в срок) в файлы не пишется.

### 2. `projects/<slug>.json` → `schemaVersion: 2`
| Поле | Тип | Условие | Кто пишет |
|---|---|---|---|
| `tasks[].originalDue` | date | допустимо **только при `due`**; у вех не бывает. Хаб ставит его при каждой записи задачи со сроком; если поля нет (правка скиллом или руками), первым сроком считается `due` | приложение: при первом задании срока копирует `due`, дальше не меняет |
| `fromIdea` | `{ ideaId: ulid, text: nonEmptyText, createdAt: dateTime }` | есть только у проекта, сделанного из идеи; неизменяемо | «Сделать проектом»: проект и удаление идеи одним коммитом |
| `doneAt` | dateTime | допустимо **только при `status = done`** | приложение: ставит при переходе в «готово», удаляет при уходе из него |

Условие для `doneAt` одностороннее (`doneAt ⇒ done`), а не «есть ⇔ done»: проект могут закрыть мимо хаба (скилл Claude, ручная правка), и тогда даты нет, а выдумывать её нельзя. Без `doneAt` плитка «готово» показывает шаг; с ним — «Опубликовано <дата>».

Схема (фрагмент; точный текст проверяется генератором Ajv в strict-режиме в задаче реализации, `type` нужен в каждом `if`/`then`):
```jsonc
"doneAt":   { "$ref": "defs.schema.json#/$defs/dateTime" },
"fromIdea": { "type": "object", "required": ["ideaId", "text", "createdAt"], "properties": {
  "ideaId": { "$ref": "defs.schema.json#/$defs/ulid" },
  "text": { "$ref": "defs.schema.json#/$defs/nonEmptyText" },
  "createdAt": { "$ref": "defs.schema.json#/$defs/dateTime" } } },
"allOf": [
  { "if": { "type": "object", "required": ["doneAt"] },
    "then": { "type": "object", "properties": { "status": { "const": "done" } } } }
]
// $defs/task:      "originalDue": { "$ref": "defs.schema.json#/$defs/date" }, "dependentRequired": { "originalDue": ["due"] }
// $defs/milestone: "not": { "required": ["originalDue"] }
```
*Исправлено 2026-09-24 по ревью:* сначала `originalDue` было обязательным при `due` в v2. Тогда задача со сроком без `originalDue` (скилл или ручная правка) делала бы весь проект нечитаемым. Теперь схема требует только обратное: `originalDue` без `due` не бывает.

**Почему новая версия, хотя обязательных полей не прибавилось.** «Сборка» здесь — версия самого хаба, которую PWA хранит в браузере устройства; она остаётся старой, пока владелец не нажмёт «Обновить». Старая сборка не знает инвариантов v2 и, сохраняя незнакомые поля, нарушит их: переведёт проект из «готово» и оставит `doneAt`, удалит срок и оставит `originalDue`. Сервер проверяет запись текущей схемой и откажет с непонятной для старой сборки ошибкой. Версия 2 делает такие файлы для старых сборок только читаемыми с понятным объяснением (ADR-003, правило 1).

### 3. Идеи, настройки, статус — остаются v1
- `ideas/<id>.json` + `project` (slug): есть ⇔ идея привязана к проекту. Хаб при удалении проекта отвязывает его идеи тем же коммитом, иначе новый проект с тем же slug молча получил бы чужие идеи. Проект удалён мимо хаба — идея показывает «проект удалён» и «отвязать». Ссылку старая сборка не ломает, поэтому версия не растёт.
- `settings.json` без изменений формата. Меняется смысл `abandonedAfterDays`: дней с max(последняя запись лога, последний коммит из `status.json`); без виджета репо — только лог.
- `status.json` (пишет Action, ADR-005) + необязательные `projects.<slug>.repo.defaultBranch` (string) и `projects.<slug>.repo.deployment.creator` (string, напр. `netlify[bot]`). Известных ботов интерфейс сопоставляет с именами провайдеров, иначе показывает `environment`.

### 4. Версии в коде
`SCHEMA_VERSION` становится таблицей по видам файлов: `project: 2`, `idea: 1`, `settings: 1`. Файл с версией выше известной для своего вида — только для чтения, как сейчас.

### 5. Проекты v1 не поддерживаются
*Исправлено 2026-09-25 по решению владельца.* Первый вариант описывал переход v1 → v2 без массовой миграции: файлы v1 читаются, первый срок берётся как `originalDue ?? due`, файл становится v2 при первой правке. Но хаб в начале разработки: в репо данных нет ни одного проекта (проверено 2026-09-25), терять нечего. Поддержка v1 — лишний код и тесты без пользы.
- Схема проекта принимает только `schemaVersion: 2`. Хаб создаёт проекты сразу в v2.
- Код чтения v1-проектов и тесты на него удаляются. Проект v1, если такой появится (руками или старой сборкой), хаб показывает среди «Файлов, которые хаб не смог прочитать», как любой файл не по схеме.
- `originalDue ?? due` остаётся, но не ради v1: `originalDue` может не быть у задачи, срок которой поставили мимо хаба.
- Защита от файлов из будущего (версия выше известной — только чтение) остаётся для v3 и дальше.

### 6. Инварианты держит нормализация перед записью, а не чтение и не правила слияния
**Слияние работает с сырыми файлами:** без подстановок и без выдачи id при разборе. *Исправлено 2026-09-24 по ревью:* первый вариант подставлял `originalDue` при чтении, и слияние видело подставленное значение из репо (base D1, моё D1, из репо «D2» — выигрывал D2, первый срок терялся).

Одна функция `normalizeProject(prev, next)` вызывается перед каждой записью проекта хабом: после правки, после слияния по ADR-004 и после выбора во «Входящих конфликтах». `prev` — моя версия файла до правки или слияния (для нового проекта — нет). Функция:
- удаляет `doneAt`, если `status ≠ done`; ставит `doneAt = сейчас`, только если в `prev` статус был не `done`, а в `next` стал `done`, и даты нет. Проекты, закрытые до v2, при правке заголовка даты не получают;
- удаляет `originalDue` у задач без `due`. Задаче со сроком без `originalDue` ставит первое найденное: `originalDue` этой задачи в `prev`, затем её `due` в `prev`, затем текущий `due`;
- ставит `schemaVersion: 2`.

Слияние по ADR-004: `originalDue` и `fromIdea` — скаляры; `doneAt` верхнего уровня — служебное время (`SERVICE_TIMES`), побеждает более позднее. Если в конфликте статуса владелец выбрал «не готово», `doneAt` убирает нормализация.

Нормализация — не единственная защита. Сервер проверяет схемой каждую запись хаба, но скилл Claude и ручные правки идут мимо хаба, а вливание ветки через merge API проверяет только файлы ветки. Поэтому экраны не рассчитывают на инварианты, которые схема не проверяет: `doneAt` при `status ≠ done` просто не показывается.

### 7. Порядок выкладки
1. Схема v2 в проверке репо данных (H2) и в скилле Claude, который пишет в репо данных, — **до** первой записи v2.
2. Новая сборка хаба на всех устройствах (PWA предложит обновление). Устройство со старой сборкой увидит v2-проекты только для чтения — это ожидаемо.

## Последствия
- Статистика дедлайнов, «Стали проектами» и «Опубликовано» считаются из файлов без журналов и истории коммитов.
- Хаб, установленный на устройстве до выкладки v2, видит v2-проекты только для чтения, пока его не обновят. *Исправлено 2026-09-25:* раньше здесь было «Первая правка каждого проекта меняет его версию; старые сборки теряют право писать в этот проект»; без поддержки v1 все проекты сразу v2.
- `normalizeProject` — единственное место инвариантов; тесты: переходы статуса, удаление срока, слияние с конфликтом статуса.
- Реализация (задача T0): `schema/*.schema.json`, примеры и `schema/README.md`, генерация `src/schema/validators.js` и `types.ts`, `src/data/model.ts` (версии по видам), `normalizeProject`, тесты. *Исправлено 2026-09-25:* отдельной задачей убрать поддержку проектов v1 (схема, примеры, тесты чтения v1) по п. 5.
