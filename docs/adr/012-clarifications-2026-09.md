# ADR-012: Уточнения по факту реализации (сентябрь 2026)

**Статус:** Принято (2026-09-29)
**Дата:** 2026-09-29
**Решает:** владелец
**Уточняет:** ADR-003 (незнакомые поля, уникальность id), ADR-004 (очередь правок, экспорт), ADR-006 (стек), ADR-007 (лимит коммита), ADR-009 (проекты v1, поле `pinned`), ADR-010 (что реализовано)

## Контекст
Глобальное ревью 2026-09-29 нашло, что код и принятые ADR разошлись. В одних местах код разумнее ADR, в других ADR обещает то, чего нет и что делать не стоит. Принятые ADR по правилам (`README.md`) не переписываются, поэтому расхождения закрываются здесь. Где этот ADR противоречит более раннему, действует этот.

## Решение

### 1. Лимиты коммита (уточняет ADR-007, STRIDE «D»)
В одном коммите — до **100 файлов**, из них картинок — не больше **20**. ADR-007 говорил «до 20 файлов»: этого не хватило для удаления тега, которое одним коммитом меняет `settings.json` и все помеченные проекты (C6b). Константы: `COMMIT_LIMIT` и `COMMIT_IMAGE_LIMIT` в `worker/write.ts`, клиент сверяется с тем же лимитом. Остальные лимиты ADR-007 (JSON до 1 МБ, картинка до 2 МБ) не меняются.

### 2. Проекты v1 читаются и правятся (против ADR-009 §5)
Проект с `schemaVersion: 1` хаб читает и даёт править. При первой записи файл становится v2 (`normalizeProject`). ADR-009 §5 «проекты v1 не поддерживаются» не действует: код чтения v1 оставлен, он небольшой и защищает от файла, написанного руками или старым скиллом по старому примеру.

### 3. Что работает без сети (уточняет ADR-004)
Очередь правок ADR-004 (одна ожидающая правка на файл, трёхстороннее слияние, «Входящие конфликты») покрывает:
- правки полей проекта;
- идеи: создание и правку.

Прямыми коммитами идут и **без сети не работают** (понятная ошибка, ввод не теряется):
- удаление проекта или идеи;
- «Сделать проектом» (создать проект и удалить идею одним коммитом);
- теги (создание, переименование, удаление со снятием с проектов);
- настройки.

Причина: это редкие действия с несколькими файлами сразу, их атомарность важнее офлайна. Главный мобильный сценарий — записать идею или поправить проект в метро — покрыт.

### 4. «Экспорт несинхронизированного» (уточняет ADR-004)
Обещанная ADR-004 кнопка — это **«Скачать неотправленное»**: JSON-файл с очередью и неразобранными конфликтами всех веток. Выход с устройства, пока есть неотправленное (очередь или конфликты), идёт через диалог, который предлагает сначала скачать файл; стереть без скачивания можно только явным выбором.

### 5. ADR-010 реализован частично, ветки заморожены
- **Реализованы:** §2 (выбор кусков длинного текста, diff3) и §4 (индикатор «Нужен вход»).
- **Отложены:** §1 (трейлер `Hub-Device` в коммитах, `lastCommit` в ответах) и §3 (вливание ветки с разбором конфликтов, `merge-plan`).
- **Ветки репо данных в интерфейсе заморожены:** что есть, работает, но не развивается. Сложное слияние веток делается на GitHub.
- **§3.6 заменён:** после вливания через merge API сервер проверяет изменённые файлы итогового коммита схемой и при ошибке возвращает предупреждения (`warnings`), а экран показывает, какой файл проверить. Откатить `main` без force нельзя, поэтому вливание не отменяется.

### 6. Стек (уточняет ADR-006)
- `motion` удалён из стека: он не использовался. Переход плитка → карточка сделан на View Transitions (todo, C4).
- `ajv` нужен только для сборки (`scripts/schema.mjs` генерирует `validators.js`), в браузер попадает сгенерированный код без Ajv. Зависимость — только для разработки.

### 7. Поле проекта `pinned` (дополняет ADR-009)
Необязательное `pinned: true` — проект закреплён и стоит первым на экране «Проекты». Добавлено по правилу 3 контракта без смены `schemaVersion`: старые сборки сохраняют его как незнакомое поле. Описание — `schema/README.md`.

### 8. `additionalProperties` (уточняет ADR-003, правило 2)
В схемах `additionalProperties` явно не задан. По JSON Schema это значит «открыто»: незнакомые поля проходят. Это и есть правило «незнакомые поля сохранять»; писать `additionalProperties: true` явно не нужно. `additionalProperties: false` по-прежнему запрещён.

### 9. Уникальность `id` в списках (уточняет ADR-003)
JSON Schema не умеет «уникальность по подполю». Уникальность `id` в `tasks`, `log`, `links`, `milestones` и `settings.tags` проверяет `parseFile` после схемы; файл с повтором — «не смог прочитать» с понятной причиной. Та же проверка — в скрипте проверки репо данных.

## Последствия
- В ADR-004, 006, 007, 009, 010 под статусом — строка «Уточнён ADR-012».
- Если ветки понадобятся всерьёз, §1 и §3 ADR-010 возвращаются новым ADR, а не молча.
- Офлайн для удаления, тегов и настроек — отдельным решением, если его отсутствие начнёт мешать.

## Простыми словами
- Хаб за раз сохраняет до 100 файлов, из них картинок до 20.
- Старые файлы проектов (версии 1) открываются и правятся, при сохранении обновляются до версии 2.
- Без интернета можно править проекты и записывать или править идеи: всё отправится само, когда появится связь. Удалить, превратить идею в проект, поменять теги или настройки можно только с интернетом.
- Кнопка «Скачать неотправленное» сохраняет в файл всё, что ещё не дошло до GitHub. Если нажать «Выйти», а что-то не отправлено, хаб сначала предложит скачать это.
- Из плана «конфликтов v2» сделаны выбор кусков текста и надпись «Нужен вход». Метка устройства в коммитах и умное вливание веток отложены, ветки больше не развиваем.
- Библиотека анимаций убрана, потому что не использовалась. Проверщик схем нужен только при сборке.
- У проекта появилась отметка «закреплён».
- Лишние поля в файлах разрешены по умолчанию, отдельно это писать не нужно.
- Одинаковые номера у задач, записей, ссылок, вех или тегов хаб ловит сам и такой файл не открывает.
