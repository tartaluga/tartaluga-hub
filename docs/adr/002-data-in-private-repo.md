# ADR-002: Данные в приватном репо, доступ через GitHub API и токен

**Статус:** Частично заменён ADR-007: токен больше не хранится в браузере, запросы к GitHub делает сервер. Механика работы с GitHub (дерево одним запросом, запись по одной, атомарные коммиты, base64) остаётся и выполняется на сервере
**Дата:** 2026-09-23
**Решает:** владелец

## Контекст
Нужно бесплатное хранилище, видимое только владельцу и доступное с трёх устройств. Кроме того, его должен уметь править Claude-скилл через git. Своего сервера нет.

## Решение
Данные лежат в приватном репо `tartaluga-hub-data`. Браузер ходит в GitHub REST API с fine-grained PAT.

- **Права браузерного токена:** только репо `tartaluga-hub-data`. Contents: read/write, Actions: write (для кнопки «Обновить сейчас», ADR-005), Metadata: read (выдаётся автоматически). **Без Workflows**: так токен не может менять `.github/workflows/` и не доберётся до секретов (ADR-005). Срок жизни — 1 год.
- **Хранение:** токен лежит в IndexedDB, а не в localStorage. Разница в безопасности небольшая, зато всё локальное состояние оказывается в одном месте. Кнопка «Выйти» стирает токен и кэш.
- **На iOS** у установленного PWA хранилище отдельное от Safari, поэтому токен вводится ещё раз уже *внутри* установленного приложения. Об этом сказано на экране входа.
- **Чтение при старте:** один запрос `GET /git/trees/{branch}?recursive=1`. Он даёт список всех файлов с их blob-sha. Сверяем sha с кэшем в IndexedDB и докачиваем только изменившиеся файлы. Никаких N+1 запросов.
- **Все запросы к API** идут с `cache: 'no-store'`: GitHub отдаёт `Cache-Control: max-age=60`, и без этого браузер может вернуть устаревший файл. Service worker запросы к `api.github.com` не кэширует никогда.
- **Кодирование:** содержимое файлов в Contents API передаётся в base64. `btoa` и `atob` ломаются на кириллице, поэтому кодируем через `TextEncoder`/`TextDecoder`. Это покрыто тестом с кириллицей и эмодзи.
- **Запись одного файла:** `PUT /contents/{path}` с `sha`. Записи выполняются **строго по одной**: GitHub прямо не рекомендует параллельные изменения в одном репо, потому что каждая запись двигает ветку.
- **Запись нескольких файлов сразу** (новый проект с обложкой, удаление проекта): одним атомарным коммитом через Git Data API (blobs → tree → commit → обновить ref без force). Либо записываются все файлы, либо ни один.
- **Картинки из приватного репо** нельзя вставить в `<img src>`: у `download_url` временный токен. Поэтому скачиваем с `Accept: application/vnd.github.raw`, кладём blob в IndexedDB и показываем через `URL.createObjectURL`.
- **401 (токен истёк или отозван):** очередь правок не трогаем, ставим её на паузу и показываем «Токен больше не работает — введи новый».

## Рассмотренные альтернативы
- **Gist:** нет папок и бинарных файлов, неудобен для скилла.
- **Supabase или Firebase:** второй сервис, аккаунт и лимиты. Скилл не сможет править данные обычным git.
- **Токен на все репо** (чтобы браузер сам видел коммиты проектов): при утечке с телефона теряется гораздо больше. Отклонено, коммиты собирает Action (ADR-005).

## Последствия
- Данные лежат в git: вся история, откат и бэкап бесплатны. Скилл работает обычными коммитами.
- Лимит API — 5000 запросов в час на токен, личному хабу этого хватает с запасом.
- Каждое сохранение — это коммит. История будет длинной, и это нормально.
