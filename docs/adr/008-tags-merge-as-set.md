# ADR-008: Теги проекта сливаются как набор

**Статус:** Принято (2026-09-24)
**Дата:** 2026-09-24
**Решает:** владелец
**Уточняет:** ADR-004 (правило «массивы без id — как скаляры»)

## Контекст
По ADR-004 массив без id сливается как скаляр. Для тегов это даёт лишние конфликты: на ПК добавил `rust`, на телефоне `go` — и файл уходит во «Входящие конфликты», хотя обе правки совместимы. Порядок тегов смысла не несёт.

## Решение
Поле `tags` верхнего уровня файла данных, если на всех трёх сторонах это массив строк (отсутствующий ключ = пустой набор), сливается как набор:
- тег, добавленный с любой стороны, сохраняется;
- тег, удалённый с любой стороны, удаляется (удаление побеждает, как у элементов, не менявшихся с другой стороны);
- порядок — удалённый, мои новые теги в конце; дубликаты схлопываются;
- пустой итог без ключа, если ключа не было с одной из сторон (как у id-массивов).

Не массив строк (недоверенные данные) — прежнее правило скаляра с конфликтом. Остальные массивы без id (`stack`, `tags` внутри элементов) — по ADR-004 без изменений.

## Последствия
- Меньше ложных конфликтов при работе с двух устройств.
- Переименование тега на одной стороне при добавлении на другой даст оба варианта; поправить руками дешевле, чем разбирать конфликт.
- Реализация: `src/data/merge.ts` (`SET_FIELDS`, `mergeStringSet`), тесты в `merge.test.ts`.
