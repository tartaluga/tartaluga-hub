# ADR-001: Хостинг на GitHub Pages в отдельной организации

**Статус:** Принято (2026-09-23: организация `tartaluga` создана, хаб в корне `tartaluga.github.io`)
**Дата:** 2026-09-23
**Решает:** владелец (Fatoom333)

## Контекст
Хаб — PWA на бесплатном GitHub Pages, поэтому репо приложения публичное. Браузер хранит токен с правом записи в приватные данные и кэш этих данных (IndexedDB).

Браузер изолирует хранилища по *origin* (схема + домен + порт). Все Pages-сайты одного аккаунта живут на одном origin `fatoom333.github.io`: `/tartaluga-hub/`, `/любой-другой-проект/` и т. д. Значит, любой будущий Pages-сайт в аккаунте (а проектов у владельца много) сможет прочитать токен и данные хаба. Для этого хватит одной XSS или одной вредной npm-зависимости в том сайте. Сейчас Pages-сайтов в аккаунте нет, но это держится на памяти, а не на устройстве системы.

GitHub Pages не даёт задавать HTTP-заголовки, поэтому CSP ставится только через `<meta>`.

## Варианты

### A. Личный аккаунт, `fatoom333.github.io/tartaluga-hub`
| Измерение | Оценка |
|---|---|
| Сложность | Низкая |
| Стоимость | 0 |
| Безопасность | Слабая: общий origin со всеми будущими Pages-сайтами аккаунта |

**Плюсы:** ничего не нужно создавать.
**Минусы:** правило «никаких других Pages в этом аккаунте» легко забыть, а цена ошибки — токен на запись.

### B. Бесплатная организация `tartaluga` → `tartaluga.github.io` *(выбрано)*
| Измерение | Оценка |
|---|---|
| Сложность | Низкая: организацию создают один раз в вебе |
| Стоимость | 0 (Free для организаций) |
| Безопасность | Свой origin, изолирован от личных Pages-сайтов |

**Плюсы:**
- Изоляция origin.
- Короткий адрес: репо можно назвать `tartaluga.github.io`, и хаб откроется в корне домена.
- У организации свой лимит в 2000 минут Actions, не общий с CI личных приватных репо (см. ADR-005).

**Минусы:**
- Организацию создаёт владелец руками: `gh` этого не умеет.
- По умолчанию организация может требовать одобрения fine-grained токенов администратором. Владелец одобряет сам себя, это один клик.

### C. Свой домен или Cloudflare Pages
Даёт заголовки и изоляцию, но добавляет второй сервис и, возможно, домен. Сейчас избыточно.

## Решение
Вариант B. Организация `tartaluga` (имя свободно на 2026-09-23). В ней лежат:
- `tartaluga.github.io` — публичный, код приложения. Хаб открывается по адресу `https://tartaluga.github.io/`.
- `tartaluga-hub-data` — приватный, данные.

Если владелец предпочтёт оставить репо в личном аккаунте, фиксируем правило: «в аккаунте Fatoom333 никаких других Pages-сайтов» и записываем его в CLAUDE.md.

Дополнительно при любом варианте:
- Строгая CSP через `<meta>`: `connect-src` только `api.github.com` и `raw.githubusercontent.com`, никаких внешних скриптов и шрифтов.
- Ноль сторонних скриптов на странице. Шрифты и иконки собираются в бандл.
- Токен никогда не пишется в логи и в URL.

## Последствия
- Проще: изоляция и отдельный лимит минут.
- Сложнее: один ручной шаг от владельца (создать организацию).
- Пересмотреть, если понадобятся HTTP-заголовки (нормальная CSP, COOP) — тогда вариант C.
