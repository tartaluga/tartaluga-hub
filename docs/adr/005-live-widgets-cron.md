# ADR-005: Живые виджеты через cron Action и ветку `status`

**Статус:** Принято (2026-09-23)
**Дата:** 2026-09-23
**Решает:** владелец

## Контекст
Нужно показывать:
- доступен ли сайт проекта;
- последние коммиты привязанного репо (включая приватные);
- статус Actions и деплоя.

Проверить доступность сайта из браузера нельзя из-за CORS. Браузерный токен видит только репо данных (ADR-002). Actions в приватных репо бесплатны до 2000 минут в месяц, и каждый запуск округляется **вверх до целой минуты**.

## Решение
- Workflow `status.yml` в `tartaluga-hub-data`: `schedule` **раз в 2 часа** плюс `workflow_dispatch` (кнопка «Обновить сейчас» в хабе).
- **Минимальная задача:** один job, без `actions/checkout`, без `setup-node` и `npm`. Скрипт на bash + `curl` + `gh api` (всё уже есть на раннере). `timeout-minutes: 2`, таймаут на каждый пинг 10 с, группа `concurrency`, чтобы запуски не наслаивались. Ожидаемо 1 оплачиваемая минута на запуск, то есть около 360 минут в месяц по расписанию.
- **Второй токен** (`STATUS_READ_TOKEN`, секрет репо данных): fine-grained, read-only, **Only select repositories** — только приватные репо, привязанные к проектам хаба. Права: Contents: read (без него GitHub не отдаёт список коммитов), Actions: read, Deployments: read, Metadata: read. Срок 1 год.
  - *Исправлено 2026-09-23 после вопроса владельца.* Раньше здесь стояло «All repositories», чтобы не перевыпускать токен. Это было ошибкой в двух местах: у fine-grained токена список репо **редактируется после создания без смены значения** (секрет обновлять не нужно), а «все репо» при утечке открывали бы код всех приватных репозиториев.
  - **Публичные репо токену не нужны:** Action читает их встроенным `GITHUB_TOKEN`.
  - **Новый приватный проект:** если Action не видит репо, в `status.json` появляется ошибка `repo_not_accessible`. Хаб показывает в карточке «добавь `<repo>` в токен статуса» со ссылкой на страницу токена.
- **Как защищён секрет.** Прочитать секрет можно только кодом, который запускается в workflow репо данных. Поэтому:
  - браузерному токену **не даём право Workflows** — без него GitHub запрещает менять файлы в `.github/workflows/`, даже при Contents: write. Утёкший браузерный токен может запустить существующий workflow, но не может подменить его на «отправь секрет мне»;
  - в workflow **нет сторонних actions** (только bash, `curl`, `gh`). Нечему украсть секрет изнутри;
  - GitHub маскирует значение секрета в логах, а скрипт не печатает заголовки запросов.
- **Запись результата:** в отдельную ветку `status` файлом `status.json`, через Contents API с повтором при конфликте sha. Так:
  - нет гонки с правками из приложения в `main`;
  - Claude-скиллу не приходится делать rebase из-за ежечасного шума;
  - история `main` остаётся чистой.
- **Коммитим только при изменении смысла:** сайт упал или поднялся, появились новые коммиты, сменился статус деплоя. Задержку пишем округлённой до корзин (<300 мс / <1 с / медленно), чтобы она не создавала коммит каждый запуск.
- **`status.json` хранит:**
  - `generatedAt`, `lastSuccess`, `errors[]` — если токен истёк, хаб покажет «виджеты не обновлялись N часов», а не станет молча показывать старое;
  - по проектам: сайт (up / down / blocked + код ответа), 5 последних коммитов, последний run Actions и деплой;
  - **счётчики коммитов по дням** (накопительно, последние 365 дней) — для тепловой карты. Снимок «последних коммитов» историю не даёт.
- **Ответы 403 и 503 от Cloudflare или антибот-защиты** показываем как «не проверить», а не как «упал»: раннер сидит в датацентре, и его часто блокируют.
- **Кнопка «Обновить сейчас»:** `workflow_dispatch` возвращает 204 без id запуска. Поэтому хаб опрашивает `status.json` в ветке `status` каждые 15 с (до 3 минут), пока не сменится `generatedAt`.

## Рассмотренные альтернативы
- **Раз в 30 минут:** около 1500 минут в месяц, на грани лимита. Отклонено.
- **Cron в публичном репо приложения** (минуты там бесплатны без лимита): логи публичного репо видны всем, в них утекут URL сайтов и имена приватных репо. Отклонено.
- **Браузер сам тянет коммиты:** нужен токен на все репо в браузере. Отклонено (ADR-002).
- **Токен статуса на All repositories:** удобнее, но при утечке открывает код всех приватных репо. Отклонено.
- **GitHub App вместо второго токена:** своё приложение GitHub ставится только на нужные репо. Workflow каждый раз получает от него временный токен, который живёт 1 час. В секретах тогда лежит ключ приложения, а не долгоживущий токен. Безопаснее: даже перехваченный токен через час бесполезен. Но настройка сложнее: зарегистрировать App, установить на репо, хранить приватный ключ, обменивать его на токен в скрипте (подпись JWT). **Отложено**, см. «Последствия».

## Последствия
- Виджеты отстают максимум на 2 часа, а по кнопке обновляются за 1–2 минуты.
- Если репо данных в организации (ADR-001), лимит минут у неё свой и не делится с CI личных репо.
- Владелец делает второй токен и кладёт его в секреты. Инструкцию дам на этапе 7.
- **Пересмотреть:** перейти на GitHub App, если приватных проектов станет много (надоест ставить галочки в токене) или если хоть раз возникнет подозрение на утечку.
