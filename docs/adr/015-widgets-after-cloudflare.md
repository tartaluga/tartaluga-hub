# ADR-015: Живые виджеты после переезда на Cloudflare

**Статус:** Принято (2026-09-29)
**Дата:** 2026-09-29
**Решает:** владелец
**Уточняет:** ADR-005 (виджеты), ADR-007 (API сервера)

## Контекст
ADR-005 писался, когда хаб ходил в GitHub токеном из браузера. После ADR-007 в GitHub ходит сервер (Cloudflare Worker) токеном установки GitHub App, и сервер сам умеет делать запросы без CORS. Нужно было решить, остаётся ли проверка в Action и как теперь устроена кнопка «Обновить сейчас». Заодно в ADR-005 остались открытыми три вопроса: как совместить «коммитим только при изменении» с «хаб видит, что виджеты не обновлялись», как считать `commitsByDay` без повторного счёта и что делать с недоверенными ссылками из данных.

## Решение
1. **Проверка остаётся в Action репо данных** (`status.yml`, раз в 2 ч плюс `workflow_dispatch`), как в ADR-005.
   - Отклонено: cron в Worker. Минуты Actions не тратит, но токен на приватный код лёг бы в сервер, открытый в интернет, а у Workers Free лимит 50 подзапросов за запуск (≈ 4 на проект, потолок ≈ 12 проектов).
2. **«Обновить сейчас»:** `POST /api/status/refresh` (только сессия владельца, те же проверки, что у других записей). Сервер вызывает `workflow_dispatch` для `status.yml` на `main` токеном установки. Право Actions: write у App уже есть (сервер запрашивает его при выдаче токена); права Workflows нет, поэтому код workflow App менять не может.
   - Ограничения частоты на сервере нет: группа `concurrency` без `cancel-in-progress` держит не больше одного идущего и одного ждущего запуска, остальные GitHub отменяет. Клиент блокирует кнопку, пока идёт опрос.
   - Ответы: 204 → `202 {ok:true}`; 404 от GitHub (нет `status.yml`) → `404 not_found «Проверка виджетов не настроена»` после проверки, что репо читается (ADR-014); 403 → `503 upstream_unavailable`.
   - Клиент после 202 опрашивает `GET /api/status` каждые 15 с до 3 минут, пока не сменится `generatedAt`.
3. **Когда Action коммитит `status.json`:** при смене смысла (как в ADR-005), **или** если прошлый `generatedAt` старше 6 ч («пульс»), **или** если запуск ручной (`workflow_dispatch`). Хаб пишет «виджеты не обновлялись N ч», если `generatedAt` старше 8 ч, и показывает `errors[]`. Итого до 4 пульсов в сутки плюс изменения.
4. **`commitsByDay`:** день — по Москве (UTC+3, без перехода на летнее время). Каждый запуск пересчитывает целиком последние 3 дня и берёт старые дни из прошлого `status.json`, поэтому повторный запуск ничего не удваивает. Первый запуск для репо набирает 365 дней, не больше 10 страниц по 100 коммитов. Дни старше 365 выбрасываются.
5. **Недоверенные данные.** Ссылки берутся из `projects/*.json` ветки `main`: первая ссылка `kind: site` и первая `kind: repo`.
   - Сайт: только `http:`/`https:`; `curl --proto =http,https --max-time 10 --max-redirs 3`, адрес после `--`, тело ответа не сохраняется.
   - Репо: только `owner/name` по `^[A-Za-z0-9-]+/[A-Za-z0-9._-]+$`, иначе ошибка проекта без запроса.
   - Хаб показывает ссылки из `status.json` через тот же фильтр `href`, что и ссылки проектов.
6. **Токены Action.** Чтение и запись репо данных — встроенный `GITHUB_TOKEN` (`contents: write`, без `actions/checkout`). Чужие репо — `STATUS_READ_TOKEN` из ADR-005; нет секрета → ошибка `token_missing` и публичные репо читаются `GITHUB_TOKEN`; 401 → `token_expired`.
7. **«Заброшен»** считается от max(последняя запись лога, последний коммит из `status.json`), как записано в `schema/README.md`.

## Последствия
- От владельца нужен только `STATUS_READ_TOKEN`; права App не меняются.
- Пуш `GITHUB_TOKEN` не запускает другие workflow, поэтому `validate.yml` на ветку `status` не срабатывает.
- Пульс добавляет до 4 коммитов в сутки в ветку `status`; `main` не затрагивается.
