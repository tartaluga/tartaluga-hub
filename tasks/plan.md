# План реализации: Tartaluga Hub

## Обзор
Личный хаб проектов: PWA на Cloudflare Workers (`hub.tartaluga.workers.dev`). Данные лежат в приватном репо; с GitHub работает только сервер через GitHub App, в браузере токена нет (ADR-007). Работает офлайн и синхронизируется со слиянием конфликтов. Дизайн «1a Визор» (`design/`). Решения описаны в [docs/adr](../docs/adr/README.md).

## Архитектурные решения (коротко)
- Сервер на Cloudflare Workers + D1: вход через GitHub или ключом доступа, сессии, запись в репо данных от имени GitHub App (ADR-007, заменяет ADR-001 и часть ADR-002). Организация `tartaluga` остаётся границей для GitHub App.
- Данные в `tartaluga-hub-data`, сервер: старт одним запросом дерева, записи строго по одной, мультифайловые изменения атомарным коммитом, base64 через TextEncoder (ADR-002).
- Контракт: `schemaVersion`, незнакомые поля сохраняются, ULID у элементов массивов, slug не меняется, одна идея = один файл (ADR-003).
- Одна ожидающая правка на файл, трёхстороннее слияние, «Входящие конфликты» (ADR-004).
- Cron раз в 2 часа, минимальный job, результат в ветке `status` (ADR-005).
- Стек: Vite, React 19, TS, vite-plugin-pwa, Zustand, idb, CSS Modules (ADR-006, ADR-012: без Motion).
- Уточнения по факту реализации — ADR-012.

## Граф зависимостей
```
JSON Schema + типы ─┬─ кодек base64/UTF-8 ─ сервер (Worker) ─ модуль записи (store) ─┬─ UI проектов
                    │                                                              ├─ Сегодня / идеи / задачи
                    └─ слияние (чистые функции) ─────────── очередь офлайн ─────────┘
дизайн-токены + оболочка (навигация, темы) ─ все экраны
Action status.yml ─ ветка status ─ виджеты, статистика
```
Порядок: сначала фундамент и самое рискованное (клиент API, кодек, слияние под тестами), потом вертикальные срезы «экран + данные».

## Фазы
Подробный список задач с критериями — в [todo.md](todo.md). Фазы 5–9 уточняются задачами перед стартом каждой фазы.

| A | 3 | Организация, репо; хостинг и вход — по ADR-007 (Cloudflare Workers, GitHub App, ключи доступа) |
| B | 4 | Фундамент: скелет, схема, кодек, клиент, модуль записи, дизайн-токены |
| C | 4 | MVP-срезы: вход, проекты (CRUD), плитки, карточка, лог, PWA |
| D | 5 | Сегодня, задачи, вехи, идеи, промт-карточка |
| E | 6 | Очередь офлайн, слияние, «Входящие конфликты» |
| F | 7 | Action статуса, виджеты, статистика |

После каждой фазы — скриншоты: десктоп и 375 px, обе темы. Затем ревью владельца.

## Риски и меры
| Риск | Влияние | Мера |
|---|---|---|
| Утечка доступа к данным | Высокое | Токена в браузере нет, сессии на сервере, узкий токен установки GitHub App, CSP без `unsafe-inline` (ADR-007) |
| Кириллица ломает base64 | Высокое | Кодек с тестом до любого UI (B3) |
| Тихая потеря данных при смене формата | Высокое | `schemaVersion`, незнакомые поля сохраняются, тесты (ADR-003) |
| Ложные и бесконечные конфликты | Среднее | `no-store`, запись по одной, «sha совпал → просто повтор» (ADR-004) |
| Кончатся минуты Actions | Среднее | Раз в 2 часа, job без npm, отдельный лимит организации (ADR-005) |
| iOS не синхронизирует в фоне | Низкое | Отправка при открытии, индикатор несинхронизированного |
| Макет есть только для «Сегодня» на ПК | Среднее | Скриншоты остальных экранов на ревью после фазы C |
