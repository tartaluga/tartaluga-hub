# Формат данных Tartaluga Hub — JSON Schema (проекты v2, остальное v1)

Схемы здесь — контракт между приложением (разных версий), будущим Claude-скиллом и ручными правками. Обоснования: [ADR-003](../docs/adr/003-data-format-contract.md). Полная документация с примерами — этап 9.

| Файл в репо данных | Схема |
|---|---|
| `projects/<slug>.json` | [project.schema.json](project.schema.json) |
| `ideas/<id>.json` | [idea.schema.json](idea.schema.json) |
| `settings.json` | [settings.schema.json](settings.schema.json) |
| `status.json` (ветка `status`) | [status.schema.json](status.schema.json) |

Примеры: [examples/valid](examples/valid) и [examples/invalid](examples/invalid) (имя файла = схема--причина отказа).

## Правила для всех, кто пишет файлы
1. **Незнакомые поля сохранять.** Прочитал → поменял своё → записал всё остальное как было.
2. **`schemaVersion`.** Если в файле версия выше той, что ты понимаешь, файл не трогать.
3. **Когда повышать версию.** Не повышать при добавлении необязательного поля или нового значения в открытый список (`link.kind`, `log.kind`). Повышать при несовместимом изменении: переименование или удаление поля, смена типа или смысла, новое обязательное поле, новое значение `status` проекта.
4. **Id** — ULID (26 символов, без букв I, L, O, U). Придумывается один раз при создании элемента и больше не меняется.
5. **Slug** проекта = имя файла, не меняется. Меняется только `title`.
6. **Создание повторяемо.** Id идеи и slug проекта выбираются до первой попытки записи и не меняются при повторах. Если файл уже есть с тем же содержимым — это успех. Если с другим — не перезаписывать: это другой объект.
7. **Даты:** дедлайны `YYYY-MM-DD` (местная дата), моменты — ISO 8601 со смещением (`+03:00` или `Z`).
8. **`updatedAt`** обновляет каждый, кто правит проект.
9. **Порядок в массивах:** `log` — новые записи в конец, но читающие сортируют по `at` сами. Порядок `milestones`, `tasks`, `links` и тегов в `settings.json` — это порядок показа.

## Версии по видам файлов (ADR-009)
| Вид | Версия | Что изменилось |
|---|---|---|
| проект | 2 | `doneAt`, `fromIdea`, `tasks[].originalDue` |
| идея | 1 | + необязательное `project` |
| настройки | 1 | формат прежний; `abandonedAfterDays` считается от max(последняя запись лога, последний коммит из `status.json`) |
| статус | 1 | + необязательные `repo.defaultBranch`, `repo.deployment.creator` |

Хаб читает проекты v1 и v2. Файлы при чтении не переписываются: v1 становится v2 при первой записи хабом. Проект с версией выше 2 — только для чтения.

### Новые поля проекта v2 и условия их присутствия
- **`doneAt`** (момент) — когда проект перешёл в «готово». Допустимо **только при `status = done`** (схема: `if doneAt then status = done`). Обратное не требуется: у проектов, закрытых до v2, даты нет и её не выдумывают.
- **`fromIdea`** `{ ideaId, text, createdAt }` — все три поля обязательны. Есть только у проекта, сделанного из идеи («Сделать проектом»: проект и удаление идеи одним коммитом). Не меняется.
- **`tasks[].originalDue`** (дата) — первый срок задачи. Допустимо **только при `due`** (`dependentRequired`). У вех не бывает. Поля нет — первым сроком считается `due` (`originalDue ?? due`).

### Идея v1: `project`
Slug проекта, к которому привязана идея; есть ⇔ идея привязана. Удаляя проект, хаб отвязывает его идеи тем же коммитом. Проект удалён мимо хаба — идея показывает «проект удалён».

### Инварианты перед записью
Хаб перед каждой записью проекта вызывает `normalizeProject(prev, next)` (`src/data/normalize.ts`):
- `status ≠ done` → `doneAt` удаляется; переход не-`done` → `done` без даты → `doneAt = сейчас`; проект уже был `done` — дата не появляется;
- задача без `due` → `originalDue` удаляется; задача с `due` без `originalDue` → берётся `originalDue` из прошлой версии, затем прошлый `due`, затем текущий `due`;
- `schemaVersion: 2`.

Скилл и ручные правки пишут мимо хаба — им нужно соблюдать те же условия (схема проверяет условия присутствия, но не «первый срок не меняется»).

## Для разработчика
```bash
npm run schema        # пересобрать src/schema/types.ts и validators.js
npm run schema:check  # то же в CI: падает, если забыли пересобрать
```
Проверяльщики генерируются заранее (Ajv standalone): CSP хаба запрещает `eval`, которым Ajv собирает их на лету.
